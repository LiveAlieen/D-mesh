## v8 — 准入模型反转（提交 015df3e）
- **原话**：「群 成员判定是该公钥是否在群黑名单里面不是群名单新成员如果自己没权限则中继到有权限的人可设自动验证群创世配置自动加群或者根据新成员发过来的消息验证是否通过通过后发签名入群消息注意黑白名单都是维护的」
- 定稿：成员判定=**不在黑名单**；白名单+黑名单**两份都全员维护**；无权限新人经中继递送到有权限者；auto=验创世配置直入 / verify=按新人消息验证；通过后发签名入群消息。

## v9 — 取消自签入群（提交 d00fb9c）
- **原话**：「自动进群是新人把种子下载的文件交给一个具有拉人进群的人由他验证文件哈希是否一致一致则那个人签名发送广播不能自签只有创建者能」
- 定稿：join **一律由具 carry 权限者签名广播，新人自签无效**；拉人者核对种子文件哈希与创世配置一致（有效种子只有创建者能签）；auto 哈希一致即放行，verify 另验消息。

## v10 — 权限层级树 + 定向申诉（提交 6b81955）
- **原话**：「权限是树形的创建者最高依次往下延续群主管理和成员，权限确定必须有高级权限签名者签名，加黑名单后可跟能解禁的成员发消息其余成员不能，」
- 定稿：层级 **创建者>群主>管理>成员**；权限确立事件须**严格高一级**签名者签发；被拉黑者唯一通道=`to` 定向申诉消息，仅具解禁权限者可收。

## v11 — 重上线自动回灌（提交 96c91c5）
- **原话**：「群成员下线重新上线后自动从多个群成员获取不在的历史消息比对差异的丢掉」
- 定稿：重连即自动「先双名单副本、后增量消息（≥3 邻居交叉比对）」，差异/单源/伪签一律丢弃+差评。

## v12 — 两把密钥分离（提交 a4ef7fe）
- **原话**：「创建者密钥和群密钥是两个密钥注意」
- 定稿：**群密钥**=建群时新生成、本群唯一、群身份锚（group_id 含 group_pub），不代表任何成员；**创建者密钥**=本人身份密钥，可跨群复用，签种子、层级最高。

## v13 / v13.1 — 在场属性与在线判定（提交 d7d84d4 / 683afee）
- **原话（v13）**：「一个人是否在线是按照他配置的最后一次发送消息时间来决定每个人都维护所有人的这个属性（区分于权限属性）」
- **原话（v13.1 定稿）**：「一个人是否在线是按照他配置的距离最后一次发送消息时间过去多长时间来决定是否上下线，每个人都维护所有人的这个属性（区分于权限属性）」
- 定稿：本地**在场表** `{pubkey → last_msg_ts, offline_after}` 与权限属性**分表**；两值仅本人自签可更新（max 合并）；**距其最后发消息的过去时长 > 其自配 offline_after → 离线**，任何新消息/心跳即回线；纯展示属性，不涉权限与核查。

## v14 — 群网盘 RAID5（提交 b3449ae）
- **原话**：「扩展群主可配置每一个群成员需要预留多少空间作为群网盘组成RAID5默认为0最高256mb」
- 定稿：群配置 `netdisk_mb`=每成员预留空间（MB），**默认 0=关闭、上限 256MB**（越界事件直接拒绝）；全员配额聚合成分条+1 轮转 XOR 校验的 RAID5（≥3 出空间成员）；单成员损失可重建、变动只补缺块重平衡；出配额可写、无配额只读。

## v15 — 退群与除名拆分（提交 e485a3a）
- **原话**：「具 kick 权限者签不等于除名必须发送特定消息不然混乱」
- 定稿：**废弃「同一条 remove 效果看签名者」**。`remove` 仅本人自签有效=退群（不进黑名单，代签一律无效且**绝不升级为除名**）；除名必须**显式发送专用 `kick` 事件**（具 kick 权限者签→删白名单+进黑名单）。

## v16 — 签名算法不固定（提交 1770821）
- **原话**：「签名算法不固定」
- 定稿：公钥/签名/proof 一律自带 `sig_alg` 标识，验签分派到**可插拔算法注册表**（默认注册 Ed25519，加新算法不改协议）；**未知 sig_alg 一律拒绝采纳+差评**；握手交换支持算法集合；不同算法密钥可同群共存。

## v17 — 实现期四处协议位缺口全部补设计（提交 f4ac265）
- **原话**：「全部升 v17 后续迭代落实」（针对 M0-M6 实现完成后集成 agent 上报的 4 个缺口：backfill Cleaner 缺 DropMember/DropBan 导出、网盘清单借 hide 会被判 malformed、Roster 缺 SetOwner 协议位、Transfer 需新 owner 联署 EndorseSig 而线协议缺位）
- 定稿：① **transfer 联署**：现任群主（或创建者）签 `{new_owner, ts}` **必须附新 owner 对事件原文（CanonicalJSON）的 `endorse_sig`**，缺联署/原文不符 → 拒+差评；**owner 指针唯一归属 = 事件流最近一条有效 transfer**，快照/回灌携带的指针仅是缓存、须能指回依据事件重验，重验不过按事件流重放恢复；旧 owner 降管理，创建者收回同样须联署。② **网盘清单传播**：走邻居隧道**独立控制帧 `netdisk_manifest`**（清单原文+上传成员签名，验签+块哈希自验后去重续传），**严禁借 hide 承载**（hide 语义锁死 `{target_msg_id}`）。③ **本地清洗**：回灌/核查发现本机脏条目 → **DropMember/DropBan 只删本机条目、不发网络事件、不构成驱逐**，正版由多数派补回（「删了等补」防本机被投毒后又当权威转发）。落实方式：后续迭代按此改代码（当前实现：清单已走独立 rpc 帧规避，其余三处待编码）。
- 落实记录（2026-09-22）：①②③ 已全部编码完成——提案定向（To=新 owner、缺联署）在 engine 主去重前拦截入收件箱、生效事件同 MsgID 不被吞；网盘清单走独立控制帧；DropMember/DropBan 本机清洗接入 backfill.Cleaner。双实例回环 E2E 验证通过（A 提案→B 收件箱→B 联署广播→A、B 双端 owner 指针一致）；E2E 揪出并修复 flood 排他 bug（生效事件 Sender=原提案者被 B 一跳转发排除、永不送达 A）。遗留观察已裁定并修复（用户拍板「本轮一并修」）：回灌重放已应用过的 join 曾按「join target already a member」误罚无辜源——改在回灌层收敛：mergeSnapshots 白名单阶段对本机已确立成员幂等跳过（与黑名单阶段 IsBlacklisted 跳过对称），不重应用、不差评任何来源，配回归测试双保险（既有成员回放零罚 + 新成员照常应用），E2E 复跑确认误罚日志清零。

## v26 — 消息归一化：统一信封 = 时间 + 三类正文 + 签名
- **原话**：「将消息归一化所有消息和命令统一格式都是时间+具体消息+签名，具体消息分为消息，命令，扩展三个类型后面是消息或命令」（2026-09-27）
- **追问裁定**：① 兼容策略 = 「断代重来」——签名原文一变，旧 `messages.jsonl` 与名单快照里的 `Proof.Raw` 在新版一律验不过，直接作废清库重跑，不加 version 位、不养双解码器。② 「命令」语义 = 「纯分类重构」——指把改名单/改群配置的既有事件归成命令大类，语义与权限模型不变；**不**引入「一条消息让对端执行某动作」的新协议语义。③ 二级类型位 = 「取消 type，靠 payload 自判别」——信封里删掉 `type` 字段。④ 扩展类边界 = 「并入扩展类，同一信封」——`presence` 心跳与网盘清单都升为正式消息走同一信封（清单不再走 transport 私有控制帧）。
- **补充裁定（开工中，2026-09-27）**：「功能不变，只改交互形式」「具体格式就按照我的要求来」——本版是**纯格式重构**：所有功能的行为、权限判定、语义一律保持不变，只把消息与命令收敛成统一信封；不得借归一化之名增删任何能力或改变任何判定路径（网盘清单并入 `ext` 同样只换承载形式，同步语义不变）。
- 定稿（PLAN 条目 19）：信封改 `{msg_id, group_id, sender, ts_ms, kind, body, to?, sig_alg, sig, endorse_sig?}`；`kind` ∈ `msg`/`cmd`/`ext`；`body` 是**恰一个键**的 tagged union `{"<名字>": <payload>}`，命令/消息/扩展的名字即由该键承载，并与 `kind` **互校**（注册表定类别，声明与实符不符即 malformed + 差评，防「把 kick 伪装成 msg」绕名单校验）。**采用 tagged union 是实现约束而非风格选择**：`eventTarget{target}` 被 remove/kick/unban/grant_admin/revoke_admin 五事件共用（`internal/group/roster.go:56`），纯字段形状在这五个上数学上不可区分。名字注册表集中在 `internal/core`，加命令=注册表加一项 + 一个解码分支，信封与验签流程不动（与 v16 算法可插拔同构）；名字属协议 token，依 v20 铁律永不进语言文件。13 个旧 type 归表：text→`msg/text`；hide/join_req/join/remove/kick/unban/perms/grant_admin/revoke_admin/transfer/netdisk→`cmd/*`（transfer 的联署仍在信封 `endorse_sig`，v17 语义不变）；presence→`ext/presence`；网盘清单→新增 `ext/manifest`。种子 `GroupConfig` 的签名路径独立于消息信封，不受影响，旧种子文件继续可用。验收在门禁/E2E 之外加一条硬要求：**`group` 侧对注册表里每一个名字做「签发→严格解码→断言生效」全表往返**（v25 网盘配额「生产端与解码端各写一份结构必然漂移」的教训制度化）。
- **落实记录（2026-09-27）**：统一信封与名字注册表落地——新增 `internal/core/body.go` 为唯一权威（`KindOf/IsKnownName/Names/MakeBody/BodyName/BodyPayload/CheckBody/TextBody/TextOf`，14 个名字），信封里 `type` 字段删除，`body=CanonicalJSON({"<名字>":payload})`；`group/message/store/netdisk/neighbor/ui/backfill` 全部改读新信封；签名原文随之改变（按「断代重来」裁定，旧库直接作废清库重跑，不留双解码器）；`internal/group/registry_contract_test.go` 钉死注册表每一项的「签发→严格解码→断言生效」全表往返；`progress.go` 补 v26 行。门禁=gofmt/vet 静默、`go test -count=1 ./...` 13 包全绿。生命周期 E2E 清库重跑 `E2E_EXIT=0`：聊天 7/7、事件 7/7、`kind↔名字互校 OK（谎报 0 / 无判别位 0）`、三类分布 `{cmd:9, ext:8, msg:4}`、错误种子 D 处理 0 次。真窗口冒烟（验收④）以「1 个 GUI 节点 A + dmesh-echo 申请端」实测：入群（两条 GUI 路径）、发言（双向，气泡/头像/名·时间行齐）、成员（层级与在场回显）、任命管理（`cmd/grant_admin` 落盘）、网盘配额（数字框 6→`{"mb":6}` 生效、12.0→18.0MiB，说明 v25 跨包契约修复在新信封下仍成立）、`cmd/netdisk` 与 `ext/presence` 混排于同一 `messages.jsonl` 各归其类、主题切 dark 并重启恢复、语言切 en 整窗重渲染、双确认取消、关窗干净退出（`local_shutdown` / `tunnel closed`）。
