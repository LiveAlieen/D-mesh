完全去中心化 P2P 群聊方案（代号：D-Mesh / Git-WG）

0. 核心结论

这是一个不依赖任何自建服务器、不依赖中心数据库、不依赖中心时钟、不依赖自建引导节点的纯 P2P 群聊方案。

它利用：

· 公共 BT DHT / PEX：做节点发现；
· WireGuard：做点对点加密传输；
· 本地 Git：做不可篡改历史存储；
· Ed25519 签名：做匿名身份与消息认证；
· 每 2 分钟提交 + 2 分钟撤回窗口：平衡 CPU 占用与可撤回体验；
· Pull 式同步：不广播，只拉取，避免流量风暴。

最终效果：群友通过一个“群组种子文件”互相发现，建立稀疏 WireGuard 网状连接，消息在本地 Git 中按批次落盘，历史不可改，撤回在 2 分钟窗口内生效。

2. 群组与身份

2.1 群组 ID

群组由“创世配置”定义：

```json
{
  "group_id": "sha256(创世配置)",
  "name": "群名",
  "version": 1,
  "created_at": 1730000000000,
  "members": [
    {
      "ed25519_pub": "base64...",
      "wg_pub": "base64...",
      "added_at": 1730000000000,
      "signature": "base64..."
    }
  ],
  "pow_difficulty": 0,
  "mode": "open"
}
```

· group_id：整个群的唯一标识，由创世配置哈希得到。
· members：成员公钥列表。不是实名身份，只是匿名公钥。
· mode：open 表示任何拿到种子的人可加入；closed 表示需要成员签名邀请。

2.2 节点身份

每个节点本地生成两对密钥：

· Ed25519 身份密钥：用于签名消息、撤回、成员邀请。
· X25519 WireGuard 密钥：用于建立加密隧道。

公钥即匿名 ID。不要求实名、手机号、邮箱。

2.3 群组种子文件

制作一个 BT 种子，内容包含：

```text
group.json
README.txt
genesis.bundle   # 可选，创世历史 Git 包
```

这个种子就是“群入口”。
群友下载并做种该文件，即可通过公共 BT DHT/PEX 找到其他群友。

注意：公共 BT DHT 的入口由 BT 客户端内置，不是本系统运营的服务器。
本系统不自建任何 DHT、Tracker、STUN、TURN、中继或信令服务器。

3. 发现层：公共 BT DHT / PEX

3.1 客户端内置 BT 节点

客户端集成 libtorrent，作为 BT 网络的一个普通 peer 加入群组种子的 swarm。

启动流程：

1. 加载 group.torrent。
2. 加入 DHT 网络。
3. 开始做种或下载。
4. 监听 peer 连接。
5. 通过 DHT 查找 info_hash 对应的 peers。
6. 通过 PEX 从已有 peer 获取更多 peer IP。
7. 滚雪球式收集群组 swarm 中的活跃节点 IP。

3.2 从 BT Peer 到 WireGuard Peer

BT peer 列表只提供 IP:Port，不直接等于群友。
需要额外握手：

1. 建立 BT peer 连接。
2. 使用 BT 扩展协议发送自定义消息：

```json
{
  "type": "wg_hello",
  "group_id": "...",
  "ed25519_pub": "...",
  "wg_pub": "...",
  "wg_listen_port": 51820,
  "timestamp_ms": 1730000000000,
  "signature": "Ed25519签名(上述字段)"
}
```

3. 对方回复 wg_hello_ack，包含同样字段和签名。
4. 双方验证：
   · group_id 是否一致；
   · 签名是否有效；
   · 公钥是否在成员列表中，或群模式是否为 open。
5. 验证通过后，把对方加入“候选 WG 邻居表”。

3.3 不依赖自建引导节点

· 客户端只使用公共 BT DHT。
· 群组种子本身是发现入口。
· 只要有一个群友在线并做种，新节点就能通过 DHT/PEX 找到他，再通过 PEX 找到更多人。
· 如果全网没有任何群友在线，新节点无法发现群，这是 P2P 的物理限制，不是服务器问题。

4. 连接层：WireGuard 稀疏网状

4.1 连接目标

不要连接所有人。
每个节点只维持 5～8 个活跃 WireGuard 邻居。

原因：

· 避免 O(N²) 隧道爆炸；
· 降低 CPU、带宽、电量消耗；
· 通过 Pull 式 Gossip 实现最终一致。

4.2 建立 WireGuard 隧道

1. 双方通过 BT 扩展协议交换：
   · 公网 IP；
   · WG 监听端口；
   · WG 公钥；
   · Ed25519 签名。
2. 尝试 UDP 打洞：
   · 双方同时向对方公网 IP:WG 端口发送 UDP 包；
   · 如果 NAT 是锥形，可打通；
   · 如果双方都有公网 IPv6，直接直连，成功率最高。
3. 打洞成功后，配置 WireGuard peer：

```ini
[Peer]
PublicKey = 对方 wg_pub
AllowedIPs = 10.66.0.2/32
Endpoint = 对方公网IP:端口
PersistentKeepalive = 25
```

4. 如果打洞失败：
   · 保持 BT 连接作为信令；
   · 每隔一段时间重试；
   · 不设中心中继，失败就失败。

4.3 邻居维护

· 每个节点维护一个邻居表。
· 定期 ping 邻居，掉线则从候选表补充。
· 优先选择：
  · IPv6 直连节点；
  · 延迟低节点；
  · 在线时间长节点。

5. 消息层

5.1 消息格式

每条消息使用 CBOR 或 JSON：

```json
{
  "msg_id": "sha256(发送者公钥 + timestamp_ms + 随机数)",
  "group_id": "...",
  "sender_ed25519_pub": "...",
  "timestamp_ms": 1730000000123,
  "type": "text",
  "content": "你好",
  "reply_to": null,
  "pow_nonce": 0,
  "signature": "Ed25519签名(除signature外所有字段)"
}
```

5.2 时间戳

· 发送时立即取本地 UTC 毫秒时间戳。
· 不依赖服务器时间，不依赖 NTP。
· 接收方只按该时间戳展示和排序。
· 如果时间戳明显异常，可标记警告，但不强制拒绝。

5.3 发送流程

1. 用户点击发送。
2. 客户端立即：
   · 生成 msg_id；
   · 打上 timestamp_ms；
   · 用 Ed25519 私钥签名；
   · 放入内存缓冲区；
   · UI 立即显示“已发送，可撤回，倒计时 2:00”。
3. 在 2 分钟窗口内，消息不写入 Git。
4. 2 分钟到，把所有未撤回消息打包成一个批次，写入本地 Git。

5.4 撤回流程

· 2 分钟内撤回：
  · 直接从内存缓冲区删除该消息。
  · 不写 Git，不留痕。
  · UI 显示“已撤回”。
· 超过 2 分钟撤回：
  · 生成一条 revoke 消息：

```json
{
  "type": "revoke",
  "target_msg_id": "...",
  "sender_ed25519_pub": "...",
  "timestamp_ms": 1730000002000,
  "signature": "..."
}
```

· 写入下一个 Git 批次。
· 其他节点拉取后，在 UI 层把目标消息标记为“已撤回”。
· Git 历史仍保留原始消息，用于防篡改审计。

6. 存储层：本地 Git

6.1 仓库结构

每个群一个本地 Git 仓库：

```text
~/.dmesh/groups/<group_id>/
  .git/
  messages/
    2025-01-01/
      1730000000000-batch.jsonl
  members/
    members.json
  group.json
```

· messages/：按批次存储消息，每行一个 JSON。
· members/：成员列表变更记录。
· group.json：群配置。

6.2 每 2 分钟提交

定时器每 2 分钟触发：

1. 取出内存缓冲区中所有未撤回消息。
2. 按 timestamp_ms 排序。
3. 追加写入 messages/日期/batch.jsonl。
4. 执行 git add 和 git commit。
5. Commit message 包含：

```text
batch_id: sha256(消息列表)
prev_commit: 上一个commit哈希
time_range: 起始时间-结束时间
sender: 本节点Ed25519公钥
signature: 本节点对batch_id的签名
```

6. 提交只写本地 Git，不推送。
7. 提交完成后，向 WireGuard 邻居宣告新 HEAD。

6.3 历史不可篡改

· Git 哈希链保证历史不可改。
· 每条消息有 Ed25519 签名。
· 即使有人修改本地文件，Git 哈希和签名会对不上。
· 撤回不删除历史，只追加 revoke 消息。

7. 同步层：Pull-based Gossip

7.1 不广播，只拉取

消息不主动推送给所有人。
节点只向邻居交换“HEAD 哈希”，然后按需拉取。

7.2 同步流程

1. 节点 A 和节点 B 建立 WireGuard 隧道。
2. A 发送：

```json
{
  "type": "head",
  "group_id": "...",
  "head_commit": "abc123...",
  "timestamp_ms": 1730000000000
}
```

3. B 对比本地 Git：
   · 如果 A 的 HEAD 是 B 的后代，B 请求拉取；
   · 如果 B 的 HEAD 是 A 的后代，B 发送自己的 HEAD；
   · 如果分叉，交换缺失的 commit 对象。
4. 拉取使用 Git 的 upload-pack 或自定义 pack 传输。
5. 拉取完成后，B 更新本地 Git，并向其他邻居宣告新 HEAD。

7.3 传播模型

· 每个节点定期（如 30 秒）向邻居询问 HEAD。
· 发现新批次就拉取。
· 拉取后，再向自己的其他邻居宣告。
· 最终所有在线节点达到一致。
· 离线节点上线后，通过邻居拉取缺失历史。

---

8. 新成员加入与历史同步

1. 新成员获得 group.torrent。
2. 用 BT 客户端下载并做种。
3. 通过 DHT/PEX 找到群友 IP。
4. 通过 BT 扩展协议交换 WG 公钥和签名。
5. 验证通过后建立 WireGuard 隧道。
6. 向邻居请求：
   · 最新 group.json；
   · 最新成员列表；
   · 从创世到当前的 Git 历史包。
7. 如果历史太大，可以只拉取最近 N 天，或从 genesis.bundle 开始。
8. 拉取完成后，新成员正式加入群聊。

9. 安全与防垃圾

9.1 匿名但签名

· 身份是 Ed25519 公钥，不是实名。
· 所有消息必须签名。
· 没有签名或签名错误的消息直接丢弃。

9.2 防重放

· 消息包含 msg_id 和 timestamp_ms。
· 接收方维护最近消息 ID 缓存。
· 重复 ID 直接丢弃。

9.3 防垃圾

· 可选 PoW：每条消息附带 pow_nonce，使 sha256(msg_id + nonce) 前 N 位为 0。
· 速率限制：每个公钥每分钟最多发 X 条。
· 黑名单：本地可屏蔽恶意公钥。
· 邻居评分：频繁发垃圾的节点降级或断开。

9.4 隐私警告

· 在公共 BT swarm 中，你的 IP 对其他 peer 可见。
· 在 WireGuard 邻居中，你的 IP 对群友可见。
· 如需隐藏 IP，需自行使用 VPN 或代理。
· 本方案不提供中心化匿名服务。

10. 客户端实现建议

10.1 技术栈

· 语言：Rust 或 Go。
· BT 库：libtorrent 绑定。
· WireGuard：wireguard-go 或内核 WG。
· Git：libgit2 或调用 git 命令。
· 存储：SQLite + Git。
· UI：TUI 或本地 Web。

10.2 核心模块

```text
dmesh/
  bt_discovery/     # libtorrent, DHT, PEX
  wg_mesh/          # WireGuard 配置与打洞
  identity/         # Ed25519, X25519
  message/          # 消息签名、时间戳、撤回
  storage/          # 本地 Git 仓库
  sync/             # HEAD 交换、Git 拉取
  ui/               # 聊天界面
```

10.3 启动伪代码

```python
def start():
    group = load_group("group.torrent")
    identity = load_or_create_identity()
    wg = init_wireguard(identity)
    bt = init_libtorrent(group.torrent)
    bt.start_dht()
    bt.start_pex()

    while True:
        peers = bt.get_peers()
        for peer in peers:
            wg_info = exchange_wg_info(peer)
            if verify(wg_info):
                try_connect_wg(wg_info)
        sync_heads_with_neighbors()
        process_incoming_messages()
        every_2_minutes(commit_buffer_to_git)
```

12. 已知限制

1. 对称 NAT 下 WireGuard 打洞可能失败，没有中继就无法连接。
2. 公共 BT DHT 可见你在下载该种子，隐私有限。
3. 2 分钟延迟：消息不是毫秒级实时，而是准实时。
4. 新成员拉取全量历史可能很慢，需要分片或创世包。
5. 群组更新复杂：成员列表变更需要广播或新种子。
6. 没有中心监管：垃圾、恶意节点只能靠本地策略过滤。

---

13. 总结

这个方案是：

· 完全去中心化：无自建服务器、无中心数据库、无中心时钟；
· 利用公共 BT DHT/PEX 做发现：群组种子即入口；
· WireGuard 做加密传输：稀疏网状，只连少数邻居；
· 本地 Git 做历史存储：每 2 分钟提交，历史不可篡改；
· 2 分钟撤回窗口：内存缓冲，撤回不落盘；
· Ed25519 匿名签名：确定谁在什么时间发了什么，但不实名；
· Pull 式同步：不广播，只拉取，避免流量风暴。

它已经是一个逻辑自洽、工程可落地的纯 P2P 群聊方案。
